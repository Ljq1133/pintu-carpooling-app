# PinTu 状态与接口契约

本文档是前端、后端、数据库和课程报告共同使用的状态基线。业务代码不得自行新增同义状态字符串。

## 1. 聚合生命周期

用户看到的一条拼车业务采用以下统一生命周期：

```text
待匹配 -> 协商中 -> 已确认 -> 履约中 -> 待付款 -> 已完成 -> 已归档
   \          \          \          \                      /
                       已取消 -> 已归档
```

当前数据库采用分阶段存储：

- `passenger_order`：承载待匹配、协商中，并在成单后同步正式订单状态。
- `match_request`：承载双方建立匹配意向的请求。
- `order_record`：承载已确认后的正式履约、支付和完成流程。
- `driver_trip`：承载司机行程及剩余座位。

前端可以把以上实体投影为连续生命周期，但写操作必须调用对应后端动作，不能直接覆盖状态字段。

## 2. 状态字典

### 2.1 乘客需求

`待匹配 / 协商中 / 已确认 / 履约中 / 待付款 / 已完成 / 已取消 / 已归档`

### 2.2 匹配请求

`待处理 / 已同意 / 已拒绝 / 已失效`

### 2.3 正式订单

`待确认 / 已确认 / 履约中 / 待付款 / 已完成 / 已取消 / 已归档`

### 2.4 司机行程

`已发布 / 已满座 / 履约中 / 已完成 / 已取消`

### 2.5 支付与评价

- 支付：`未支付 / 已支付 / 已退款`
- 评价：`未评价 / 已评价`

## 3. 当前实现与目标流程

当前 MVP 在司机接受匹配请求时直接创建 `已确认` 正式订单。该行为用于维持现有跨端演示闭环。

目标流程将在“协商聊天与双向确认”阶段替换为：

1. 任一方发起匹配请求。
2. 对方接受后进入 `协商中`，建立订单级会话。
3. 双方协商价格、时间、人数和上车点，生成版本化契约快照。
4. 乘客和司机分别确认同一版本。
5. 后端在事务中创建或确认正式订单、扣减座位，状态进入 `已确认`。

在该阶段完成前，接口文档必须明确当前 MVP 行为，不能将其描述为已经实现双向确认。

## 4. HTTP API 基线

服务启动后：

- OpenAPI JSON：`http://127.0.0.1:8080/api-docs`
- Swagger UI：`http://127.0.0.1:8080/swagger-ui.html`
- 健康检查：`http://127.0.0.1:8080/api/health`

`docs/A组接口文档.md` 负责业务说明，运行时 OpenAPI 负责控制器、参数和响应结构的事实校验。两者有冲突时，应修复代码或文档，不能长期保留双重定义。

## 5. 时间与位置契约

- 数据库业务时间统一使用 `DATETIME`，Java 持久层统一使用 `LocalDateTime`。
- API 请求和响应统一使用 `yyyy-MM-dd HH:mm`，业务时区固定为 `Asia/Shanghai`。
- 起终点经纬度使用 WGS-84 语义，数据库类型为 `DECIMAL(10,7)`，Java 类型为 `BigDecimal`。
- 位置坐标目前为可选字段，未接入地图 SDK 时仍可使用文本地址；接入定位后应同时提交地址与坐标。
- 正式订单保存匹配时的地址、坐标和计划出发时间快照，并记录实际出发、实际到达时间。

## 6. 用户黑名单契约

乘客和司机共用账户级黑名单。黑名单只影响双方后续推荐，不自动取消已经存在的匹配请求、正式订单或履约流程。

```http
GET /api/privacy/blacklist
POST /api/privacy/blacklist
DELETE /api/privacy/blacklist/{blockedUserId}
```

- `GET` 只返回当前登录用户自己的黑名单，按创建时间倒序排列。
- `POST` 请求体为 `{ blockedUserId, reason? }`；禁止拉黑自己，重复拉黑保持幂等。
- `DELETE` 只解除当前用户对目标用户的拉黑，重复解除保持幂等。
- 黑名单列表只展示脱敏姓名、角色、原因和创建时间，不返回手机号。
- 匹配推荐按双向关系过滤：任意一方拉黑对方，乘客推荐司机和司机推荐乘客均排除该组合。

## 7. 行程安全接口契约

乘客与司机共用账户级安全接口，但只能读取和修改当前登录账户自己的紧急联系人。

```http
GET /api/safety/emergency-contacts
POST /api/safety/emergency-contacts
PUT /api/safety/emergency-contacts/{contactId}
DELETE /api/safety/emergency-contacts/{contactId}
POST /api/safety/orders/{orderId}/alerts
```

- 联系人保存字段为 `{ name, phone, relationship, isPrimary }`；编辑时 `phone` 留空表示保持原号码。
- 手机号使用 `SensitiveDataCrypto` 加密存储，响应只返回 `phoneMasked`，不返回明文手机号。
- 每个账户最多一个主要联系人；设置新主要联系人时自动取消原主要联系人。
- 报警仅允许订单乘客或司机在正式订单状态为 `履约中` 时触发。
- 报警请求为 `{ alertType, longitude?, latitude?, details? }`；定位失败时经纬度可以为空。
- 当前 `PoliceGateway` 使用课程 `MockPoliceGateway`，只写入报警记录并返回 Mock 回执，不会真实联系警方。
- 报警不会取消订单，也不会改变订单、支付或信用状态。
