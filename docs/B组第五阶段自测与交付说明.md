# B 组第五阶段自测与交付说明

本文用于 B 组乘客端 MVP 提交前自测、截图、交付和联调说明。当前结论只覆盖 B 组乘客端和本地 mock / API adapter，不代表 A / C 组真实联调已经完成。

## 1. 当前交付结论

当前 B 组乘客端已经达到可提交的代码基线：

- 乘客端 MVP 主流程已实现：发布拼车需求 -> 推荐司机 -> 发起拼车请求 -> 等待司机确认 -> 司机同意后进入进行中 -> 行程开始 / 到达 -> 乘客付款 -> 评价 -> 订单历史。
- 页面动作已统一经过 `src/api/passengerApi.js`，当前默认使用 `src/api/passengerApi.mock.js`，后续真实接口优先替换 adapter。
- B 组接口需求、后续扩展规划和联调检查项已整理在 `docs/B组接口需求清单.md` 和 `docs/B组开发计划.md`。
- 当前未实现真实地图、真实支付、真实登录鉴权、司机端、管理端和后端数据库。

## 3. 浏览器手测清单

由于当前环境没有可用的浏览器点击自动化工具，以下清单需要提交前人工在浏览器复核。运行方式：

```bash
npm run dev
```

打开：

```text
http://127.0.0.1:5173
```

### 3.1 主流程

1. 进入 `06 乘客端 MVP 工作台`。
2. 在乘车页确认默认显示 mock 地图区域、出发地、目的地、出发时间、人数和备注。
3. 点击“发布拼车需求”，页面进入推荐司机页。
4. 推荐页显示符合规则的司机卡片，点击“发送拼车请求”。
5. 页面自动回到乘车页，显示等待司机确认和 `待确认` 状态。
6. 点击 `mock 司机同意`，进入实时行程卡片。
7. 点击 `mock 行程开始`，状态变为行程中。
8. 点击 `mock 到达目的地`，状态变为待付款并显示付款入口。
9. 点击模拟付款，订单进入已完成，乘车页显示付款完成页。
10. 打开评价入口，提交评价。
11. 进入订单页，切到已完成，查看轻量行程摘要和评价结果。

### 3.2 异常流程

- 清空出发地后点击发布，应提示“请填写出发地”。
- 清空目的地后点击发布，应提示“请填写目的地”。
- 乘车人数设为 0 后点击发布，应提示“乘车人数不能小于 1”。
- 推荐页不应展示满座、信用分低于 80、顺路度低于 60% 的司机。
- 发起请求后点击 `mock 司机拒绝`，乘车页应显示拒绝原因和“重新选择司机”入口。
- 未点击 `mock 到达目的地` 前，不应出现付款入口。
- 未付款前，不应出现可提交评价的入口。
- 已完成订单不应再次付款。

## 4. 建议截图点

用于课程报告或功能展示时，建议截以下页面：

1. 乘车页初始表单：展示手机端结构、mock 地图、起终点、时间选择、人数和发布按钮。
2. 推荐司机页：展示 `MatchCard`、司机车辆信息、信用分、顺路度和价格。
3. 等待司机确认页：展示乘客发起请求后的等待状态。
4. 实时行程页：展示司机位置、预计到达、距离、车辆、路线和费用。
5. 付款完成 / 评价页：展示订单完成和评价入口。
6. 订单页已完成列表：展示 `OrderCard` 和轻量行程摘要。
7. 联调准备页：展示演示账号、接口需求、状态字段和 A / C 联调检查项。

- B 组 API adapter。

## 6. 待 A / C 组联调事项

- A 组确认 `PassengerOrder`、`MatchRequest`、`OrderRecord` 是否分表，以及对应 ID 字段。
- A 组确认乘客端展示状态是否采用 `待匹配 / 进行中 / 已完成 / 已取消`，或由 adapter 映射七阶段状态。
- A 组提供发布订单、订单列表、推荐司机、匹配请求、付款、评价接口。
- C 组确认 B 组发起的匹配请求能在司机端展示。
- C 组确认司机同意 / 拒绝后，B 组乘车页能同步状态。
- C 组确认司机送达后，B 组是否只开放付款入口，而不新增付款前主状态。
- 管理端确认能看到 B 组创建、进行中、已完成的订单。
