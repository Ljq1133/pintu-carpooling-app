# PinTu 技术路线决策

## 1. 客户端

PinTu 课程交付采用 Vue 3 + Vite 的响应式 Web/PWA：

- 一套代码覆盖乘客端、司机端和管理端。
- 通过浏览器定位、通知、语音等 Provider 接口承接设备能力。
- 保留封装为 PWA、WebView 或迁移到 Uni-app 的边界，但不在报告中宣称当前已经交付原生 App 或小程序。
- UI、路由、状态管理和 API 层按领域拆分，禁止页面直接依赖共享 Mock 数组。

选择该路线是为了让报告与当前可运行代码一致，并在课程周期内优先保证完整业务闭环、测试和部署。

## 2. 后端

后端采用 Spring Boot 模块化单体：

- 认证、用户、车辆、匹配、协商、订单、支付、评价、信用、审核、申诉、通知按领域划分包和服务边界。
- 所有模块共享一个部署单元和数据库事务，适合课程规模下的强一致订单流程。
- 地图、短信、支付、对象存储、消息队列等外部能力统一通过 Provider 接口接入。
- 领域事件和 Outbox 用于解耦通知、审计、信用与统计，未来可按模块演进为微服务。

报告中的“微服务架构”统一调整为“模块化单体，具备可演进的服务边界”。除非仓库中存在独立部署、服务发现、网关和跨服务一致性实现，否则不宣称已完成微服务部署。

## 3. 基础设施

- 主数据库：MySQL 8，Flyway 管理版本。
- 测试数据库：H2 MySQL 兼容模式。
- Redis：验证码、限流、短期会话、锁和热点缓存的可选运行依赖。
- RabbitMQ：课程版先实现进程内事件与 Outbox，同一接口可替换为消息队列。
- 附件：本地文件 Provider 用于课程演示，可替换为 MinIO 或云对象存储。

## 4. 一致性规则

1. 运行代码和自动化测试是事实来源。
2. OpenAPI 是 HTTP 契约来源。
3. Flyway 是数据库结构来源。
4. 报告、UML 和截图必须从以上事实来源更新，不得描述尚未实现的生产能力。
